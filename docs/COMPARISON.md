# Comparison

## Access Orientation Protocol vs linear workflow

A linear workflow usually assumes that work can be decomposed into ordered steps that move from input to output. It tends to optimize completion, handoff, and throughput.

Access Orientation Protocol addresses a different problem. It asks whether the system is correctly calibrated, entering through the right anchor, maintaining integrity through change, and validating action through reality.

Key differences:
- a linear workflow prioritizes sequence; AOP prioritizes orientation;
- a linear workflow can start from assigned work; AOP requires Resonance (Self) before meaningful entry;
- a linear workflow may end at execution; AOP is incomplete without Resonance (World);
- a linear workflow tracks steps; AOP examines trajectory as pattern over time.

## Access Orientation Protocol vs agent runtime

An agent runtime manages execution: tool use, memory, planning loops, policies, and action dispatch.

Access Orientation Protocol is not a runtime. It is a meta-orientation layer that can inform how a runtime should enter, frame, transition, and validate work.

Key differences:
- a runtime executes operations; AOP constrains how operations should be oriented;
- a runtime can function without self-calibration; AOP treats self-resonance as a mandatory boundary;
- a runtime may optimize task completion; AOP evaluates integrity, drift, and world feedback.

## Access Orientation Protocol vs decision engine

A decision engine selects among options according to rules, objectives, or learned policies.

Access Orientation Protocol does not primarily choose among alternatives. It structures the conditions under which choosing, acting, and learning become more grounded.

Key differences:
- a decision engine answers "which option?"; AOP asks "from what state, through what transition, and with what validation?";
- a decision engine may be correct within a bad frame; AOP attempts to improve the frame itself;
- a decision engine can terminate at choice; AOP continues through movement, trajectory, and world resonance.

## Summary

Access Orientation Protocol should be understood as a meta-orientation architecture. It can sit above workflows, runtimes, decision engines, and benchmarking layers, but it is not reducible to any of them.
