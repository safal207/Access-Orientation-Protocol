# Anti-Patterns

This document describes ways the Access Orientation Protocol should not be used.

## Treating the protocol as a productivity funnel

The protocol is not a motivational sequence for producing more output. When used this way, Resonance (Self) becomes a ritual, Orientation collapses into task planning, and Resonance (World) is reduced to delivery metrics.

## Using the protocol to justify delay

Because the protocol values calibration and transition, it can be misused to rationalize avoidance. Endless self-checking, assembly, or reframing is not fidelity to the protocol; it is failure to move.

## Collapsing orientation into planning

Orientation restores coordinates, relations, and direction. If it is reduced to backlog management or task routing, the protocol loses one of its core distinctions.

## Replacing world resonance with consensus

Agreement within a team, model, or institution is not the same as validation by reality. Consensus can still be detached from external conditions.

## Treating trajectory as a reporting artifact

Trajectory is the observed pattern of motion over time. It should not be flattened into a dashboard, timeline, or list of completed steps without interpretive context.

## Weaponizing self-resonance

Self-resonance is meant to improve honesty about actual state. It should not be used to excuse harmful behavior, avoid accountability, or elevate subjective feeling above consequences.

## Converting the protocol into doctrine

The protocol is a conceptual architecture, not a closed belief system. If its terminology becomes rigid ideology, the protocol begins to undermine its own commitment to reality contact.
