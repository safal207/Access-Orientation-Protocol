# Technical Brief

## Protocol type

Access Orientation Protocol is a loop-based orientation protocol for living systems. It provides a structured way to move from internal calibration to externally tested action while preserving continuity across state changes.

## Core principle

Action is reliable only when it emerges from a correctly oriented loop:
**Resonance (Self) -> Access Point -> Assembly -> Orientation -> Transition -> Movement -> Trajectory -> Resonance (World)**.

The loop is incomplete if external reality does not answer the cycle.

## Architecture

The protocol contains eight ordered stages with two mandatory boundaries:
- **Mandatory entry boundary:** Resonance (Self)
- **Mandatory completion boundary:** Resonance (World)

Internal stages:
1. Access Point
2. Assembly
3. Orientation
4. Transition
5. Movement
6. Trajectory

The stages are not a rigid productivity workflow. They are a conceptual architecture for preserving integrity between state, action, and feedback.

## Invariants

- The protocol is a loop, not a pipeline.
- Resonance (Self) is required before meaningful entry.
- Resonance (World) is required before the cycle can be considered complete.
- Orientation is restoration of coordinates and direction, not simple planning.
- Transition must preserve continuity; abrupt rupture degrades integrity.
- Trajectory is the observed pattern of motion over time.
- The protocol does not guarantee truth and does not eliminate self-deception.

## Failure conditions

The protocol degrades when:
- self-resonance is false, skipped, or performative;
- the access point is misidentified;
- assembly accumulates irrelevant material;
- orientation is replaced by urgency, ideology, or narrow planning;
- transition is forced or bypassed;
- movement occurs without centered orientation;
- trajectory is inferred from isolated events rather than patterns over time;
- world resonance is replaced by internal satisfaction, agreement, or narrative closure.

## Applicability

The protocol is applicable to:
- **Humans:** personal orientation, decision contexts, recovery from drift;
- **AI agents:** state-aware prompting, context assembly, execution gating, post-action validation;
- **Teams:** shared framing, coordination, transition management, feedback loops;
- **Adaptive systems:** control logic that must relate internal state to external response;
- **Benchmarking systems:** orientation-aware evaluation, reproducibility, long-run behavior, and world-transfer checks.

It should be treated as a meta-orientation layer that can sit above execution logic, benchmarking logic, or both, not as either logic itself.
